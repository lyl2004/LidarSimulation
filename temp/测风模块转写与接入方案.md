# 测风模块转写与接入方案

更新日期：2026-09-18。下一阶段以 `temp/simulation_fft_end.m` 为接收器严格样例，以当前大气散射/回波代码为信号来源，先完成可逐步对照的 MATLAB 兼容接入，再扩展为同一事件源和更完整的物理模型。

## 1. 共识与边界

流程分为两部分：

```text
大气散射与回波 → 距离分辨平均回波功率、波长、脉宽和场景元数据
接收器         → 光功率转平均光子数 → MATLAB 风格探测/事件 → FFT 与时间差
```

这种分层合理，但当前不是完整端到端单光子链路：`temp/lidar_1d` 主要通过雷达方程输出 `power_signal_raw`，不是逐个返回光子；当前接收器再据此合成理想相干拍频。

当前散射代码的能力：

- `temp/lidar_1d`：Mie/T-Matrix 后向散射、消光、双程透过率和距离门平均功率，不输出接收单光子时间戳。
- `src/mie_core.py`：Python 偏振蒙特卡洛统计吸收、透射、边界后向比例和角度分布，不形成激光雷达孔径事件序列。
- `src/julia/iitm_physics.jl`：可选 `collect_lidar_observation`，按接收锥和距离 bin 汇总加权 `echo_I/Q/U/V`、`echo_power`、`echo_event_count`；这些是路径贡献，不是 SPAD 离散计数，尚未接入测风支路。

风速页面当前读取 `power_signal_raw`，其单位为 W、含义为选定距离门平均回波功率。

## 2. MATLAB 接收器严格样例

参考：`temp/simulation_fft_end.m`。它包含两条独立链路，第一阶段分别复刻，不能未经说明合并。

### 2.1 概率序列 FFT 链

严格保持：

```text
P1/P2、拍频和时间 bin
 → R_inst → p(k)=1-exp(-R_inst) → 死时间递推 q(k)
 → xcorr(q,'biased') → corr_noisy
 → fft、单边幅度谱 → 搜索带最大峰 → 速度换算
```

固定并记录 `bin_width`、`T_total`、`N_local_pers`、`N_signal_pers`、`tau_dead`、`noise_amp`、参考频率、搜索频带、FFT 长度和幅度谱归一化。

### 2.2 `single_pulse()` 双通道链

严格保持独立双通道泊松抽样、探测效率、非延长死时间、后脉冲、事件时间戳、全组合时间差和 MATLAB histogram 边界。

MATLAB 原文件中第一条 FFT 链和第二条事件链不共享事件；`single_pulse()` 内部拍频固定为 80 MHz，死时间也与前面的 30 ns 不同。兼容模式保留实际行为并标注；修正版另设模式。

## 3. 下一步：MATLAB 兼容接入

### 3.1 冻结接口

大气模块提供：

```text
range_m, pulse_width_s, dt_s, wavelength_m,
P_signal(t), P_background(t)
```

接收器转换为平均光子数：

```text
μ(k) = P(k)·dt / (h c / λ)
```

本振、参考频差、接收窗口、效率、死时间、后脉冲和随机种子属于接收器配置。效率只施加一次，已有光路效率不能重复计算。

### 3.2 三种模式

- **`matlab_compat_raw`**：逐步复刻 MATLAB，保留两条独立链路、原始参数差异、相关函数加噪和幅度谱口径，用于逐数组和统计对照。
- **`matlab_compat_corrected`**：统一死时间、速度输入、单位、随机种子和命名，但仍保留 MATLAB 概率 FFT 与双通道事件两条结果。
- **`unified_event_mode`**：同一批 SPAD 事件同时生成通道 1 FFT 和双通道时间差；物理上更连贯，但不属于严格 MATLAB 复刻，必须独立标识。

### 3.3 验证顺序

1. 无噪声、无随机探测：逐点比较 `p`、`q`、`xcorr`、频率轴和主峰。
2. 固定光子率：比较单通道均值、泊松方差和死时间抑制。
3. 固定种子：比较事件数、后脉冲和时间差分布；不同语言不要求逐事件相同，但统计量须一致。
4. 验证零/正/负速度、频带边界、无事件和弱信号失败。
5. 接入各场景 `power_signal_raw`，记录功率、光子率、事件数、峰值、SNR 和成功率。

不能只用一次主峰验收；每个工况需报告峰值偏差、速度误差分布、有效率和无信号误报率。

## 4. 大气散射改进路线

### 阶段 A：保持平均功率主体

继续使用现有 `β(R)`、`α(R)`、双程透过率、overlap 和 `P_signal(R)`。先选定距离门，将平均功率转为接收器的每 bin 平均光子数，建立可靠 MATLAB 对照。

### 阶段 B：接入距离分辨蒙特卡洛

Julia `lidar_observation` 可作为后续来源，但必须明确：`echo_power` 是加权回波贡献，`echo_event_count` 是路径/贡献计数，不是 SPAD 计数。需记录距离 bin、接收锥、重叠、透过率和蒙特卡洛误差，转换为光子均值后再交给接收器。

### 阶段 C：加入速度和复场

真实有风扩展需要距离/粒子类别速度、速度分布和湍流谱宽、多距离叠加、散射复振幅/相位、激光线宽、本振相噪、频率抖动、散斑和平台运动。仅凭平均 `power_signal_raw` 无法恢复这些量；当前余弦拍频只能作为明确标注的理想扩展。

## 5. 首版实现压缩记录

- `src/wind_io.py`：场景功率和仪器元数据读取。
- `src/spad_detector.py`：泊松探测、效率、非延长死时间、暗计数、无级联后脉冲。
- `src/wind_receiver.py`：当前为理想单距离混频、事件周期图、白化寻峰和双通道时间差，尚未严格复刻 MATLAB。
- `src/wind_worker.py`：后台计算和 JSON 输出。
- `app/wind_ui.py`、`app/demo_ui.py`：页面整合。

已知差异：当前窗口 200 ns、频率格 5 MHz；使用去均值 Hann 事件功率谱和多脉冲平均；使用独立恒定光照噪声参考、亚 bin 插值和显著性筛选；两图共享事件；默认最低测风 SNR 为 -6 dB。它们均不能冒充 MATLAB 严格结果。

## 6. 结果和失败状态

结果记录来源运行、场景、距离、`P_signal`、波长、脉宽、光子换算、全部接收器参数、算法模式/版本、FFT 轴和口径、峰值、参考频率、时间差 bin、事件统计、设定/估计速度、误差、SNR、有效状态和失败原因。

无事件、噪声底不可估计、峰在边界、统计显著性不足、信号或元数据缺失时不得报告成功测速。`SNR < -6 dB` 只是当前演示阈值，不是物理普适阈值；应由 MATLAB 对照样本和器件标定确定。

## 7. 实施顺序与交付标准

1. 冻结 MATLAB 参数、单位和两条链路口径。
2. 新增 MATLAB 兼容接收器，不删除当前接收器，输出两套结果对照。
3. 建立逐数组、频率轴、峰值、事件统计和直方图回归测试。
4. 接入 `power_signal_raw`，形成各场景功率—光子率—测速成功率表。
5. 针对弱场景调整物理参数和失败提示，不通过放宽阈值伪造成功。
6. 增加同一事件源模式，明确标记其与 MATLAB 的差异。
7. 再评估 Julia 接收锥蒙特卡洛和速度/复场扩展。

最终验收必须同时满足：MATLAB 兼容模式可复现样例频率轴、主峰和速度换算；散射功率通过明确光子换算进入接收器；弱信号输出可解释诊断；兼容模式、统一事件模式和物理扩展模式不混淆；UI 精度、SNR 和有效状态与实际分辨率及统计证据一致。
