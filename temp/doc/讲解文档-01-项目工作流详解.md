# 项目工作流详解

本文档说明当前 1D LiDAR 仿真评估项目中，前端输入如何进入计算链路，如何产生中间结果，最终如何落盘并被界面读取。

## 1. 总体链路

项目的主链路可以概括为：

```text
前端参数控件
-> 收集为 overrides
-> 写入 temp/lidar_1d/param_overrides.json
-> make_final_figures.py 拼接计算命令
-> lidar_1d_simulation.py 读取参数并执行计算
-> 生成 summary.json / params.json / CSV / PNG / SVG
-> UI 读取结果文件并展示图表、表格和导出项
```

核心特点是：前端不直接在内存中调用物理计算函数，而是将参数写入文件，再由独立计算脚本完成仿真，结果也统一以文件形式输出。

## 2. 前端输入层

前端入口文件：

```text
app/demo_ui.py
```

主要入口函数：

```text
index()
```

`index()` 会加载当前活动结果的 `summary.json`，再构建左右两侧界面。

左侧参数面板由以下函数构建：

| 参数组 | 构建函数 | 说明 |
|---|---|---|
| 仪器参数 | `_build_instrument_editor()` | 波长、峰值功率、脉宽、接收半径、光学效率 |
| 接收端噪声 / SNR | `_build_noise_editor()` | 量子效率、背景光、暗电流、读出噪声、平均脉冲数等 |
| 大气分子参数 | `_build_global_editor()` | 分子消光、分子后向散射、分子退偏振比 |
| 雾场景参数 | `_build_fog_editor()` | 辐射雾、平流雾的粒径谱和折射率 |
| 霾场景参数 | `_build_haze_mode_editor()` | 四类霾的 fine/coarse 模态参数 |
| 雨场景参数 | `_build_rain_editor()` | 小雨、中雨、大雨的降雨率 |

所有数值输入通过 `_num()` 注册，所有开关输入通过 `_switch()` 注册，最终都进入全局 `_inputs` 字典。

## 3. 参数收集层

用户点击“写入并重算”后，进入：

```text
app/demo_ui.py::_do_recompute()
```

该函数调用：

```text
app/demo_ui.py::_collect_overrides()
```

`_collect_overrides()` 会把前端控件值整理为统一结构：

```json
{
  "fog": {},
  "haze": {},
  "rain": {},
  "cli": {},
  "instrument": {
    "laser_peak_power_W": 50.0,
    "pulse_width_s": 2e-7,
    "receiver_radius_m": 0.05,
    "optical_efficiency": 0.8,
    "receiver_noise": {}
  }
}
```

其中仪器参数会被用于计算系统常数：

```text
C = P0 * c * tau / 2 * receiver_area * optical_efficiency
```

计算得到的 `C` 会写入：

```text
cli["system-constant"]
```

后续雷达方程使用该值计算回波功率。

## 4. 缓存判断层

在启动计算前，前端会先判断当前参数是否已经有可复用结果。

主要函数：

| 文件 | 函数 | 作用 |
|---|---|---|
| `app/demo_ui.py` | `_compute_current_identity()` | 根据当前 UI 参数生成缓存身份 |
| `src/cache_keys.py` | `fog_cache_key()` | 生成雾光学缓存 key |
| `src/cache_keys.py` | `haze_cache_key()` | 生成霾光学缓存 key |
| `src/cache_keys.py` | `haze_mueller_key()` | 生成霾 Mueller/偏振缓存 key |
| `src/cache_keys.py` | `rain_cache_key()` | 生成雨光学缓存 key |
| `src/cache_keys.py` | `instrument_hash()` | 生成仪器参数 hash |
| `src/cache_keys.py` | `noise_hash_from_overrides()` | 生成噪声参数 hash |
| `src/cache_runtime.py` | `build_run_index()` | 建立历史结果索引 |
| `src/cache_runtime.py` | `classify_identity_match()` | 判断完整命中、部分命中或未命中 |

判断结果分为三类：

| 结果 | 行为 |
|---|---|
| 完整命中 | 直接切换到历史结果，不启动计算 |
| 光学部分命中 | 复用部分光学缓存，补算输出 |
| 未命中 | 执行完整计算 |

## 5. 重算调度层

当需要重算时，`_do_recompute()` 会执行以下动作。

第一步，写入参数覆盖文件：

```text
temp/lidar_1d/param_overrides.json
```

第二步，写入 pending 状态文件：

```text
temp/lidar_1d/runtime_state/pending_run.json
```

第三步，启动计算包装器：

```text
temp/lidar_1d/make_final_figures.py
```

实际命令大致为：

```powershell
<mie_python> temp/lidar_1d/make_final_figures.py --precision fast
```

`mie_python` 由：

```text
src/path_resolver.py::resolve_mie_python_executable()
```

统一解析。

## 6. 包装器层

包装器文件：

```text
temp/lidar_1d/make_final_figures.py
```

它不做物理计算，只负责准备并启动核心仿真脚本。

主要函数：

| 函数 | 行为 |
|---|---|
| `load_cli_overrides()` | 读取 `param_overrides.json` 中的 `cli` 参数 |
| `build_command()` | 拼接 `lidar_1d_simulation.py` 的命令行 |
| `resolve_julia_cmd()` | 查找 Julia 可执行文件 |
| `main()` | 执行子进程 |

精度档位定义在：

```text
PRECISION_PRESETS
```

它控制：

| 精度项 | 说明 |
|---|---|
| `fog-grid` | 雾粒径积分网格 |
| `rain-grid` | 雨滴直径积分网格 |
| `haze-mie-reference-grid` | 霾 Mie 参考网格 |
| `tmatrix-n-radii` | T-matrix 半径采样数 |
| `tmatrix-nr` | T-matrix 径向参数 |
| `tmatrix-ntheta` | T-matrix 角向参数 |
| `discrete-angle-bins` | Stokes 偏振传播角度离散数 |
| `stokes-max-orders` | 最大散射阶数 |

包装器最终调用：

```text
temp/lidar_1d/lidar_1d_simulation.py
```

## 7. 核心计算输入解析层

核心入口：

```text
temp/lidar_1d/lidar_1d_simulation.py::run()
```

它依次完成：

| 步骤 | 函数 | 中间结果 |
|---|---|---|
| 读取前端覆盖参数 | `load_param_overrides()` | `overrides` |
| 解析仪器参数 | `resolve_instrument_parameters()` | 激光功率、脉宽、接收面积、系统常数 |
| 解析噪声参数 | `resolve_noise_model()` | `NoiseModel` |
| 生成距离网格 | `np.arange()` | `range_m` |
| 构造默认雾场景 | `default_fog_specs()` | 默认雾参数 |
| 构造默认霾场景 | `default_haze_specs()` | 默认霾参数 |
| 构造默认雨场景 | `default_rain_specs()` | 默认雨参数 |
| 应用前端覆盖 | `apply_fog_overrides()` 等 | 本次实际计算参数 |

随后初始化 `summaries` 字典。该字典最终写入 `summary.json`。

## 8. 光学参数计算层

核心计算先得到每个场景的光学参数。

主要中间结果：

| 字段 | 含义 |
|---|---|
| `alpha_particle` | 粒子消光系数 |
| `beta_particle` | 粒子后向散射系数 |
| `alpha_total` | 分子 + 粒子的总消光系数 |
| `beta_total` | 分子 + 粒子的总后向散射系数 |
| `depol_ratio` | 退偏振比 |
| `alpha_rel_grid_error` | 消光网格误差估计 |
| `beta_rel_grid_error` | 后向散射网格误差估计 |

分场景计算函数：

| 场景 | 函数 | 行为 |
|---|---|---|
| 雾 | `compute_fog()` | 基于雾滴对数正态粒径谱和 Mie 散射计算 |
| 霾 | `compute_haze_with_tmatrix()` | 细模态 Mie + 粗模态可选 T-matrix |
| 霾偏振 | `build_haze_mueller_library()` | 构建 Mueller 角分布库 |
| 雨 | `compute_rain()` | Marshall-Palmer 雨滴谱 + Mie 散射 |

T-matrix 计算通过：

```text
run_tmatrix_batch()
```

调用 Julia 脚本：

```text
temp/lidar_1d/julia/tmatrix_batch.jl
```

## 9. 回波、噪声、SNR 与退偏振计算层

得到 `alpha_total` 和 `beta_total` 后，计算雷达回波功率：

```text
P(R) = C * O(R) * beta * exp(-2 * alpha * R) / R^2
```

对应函数：

```text
lidar_power()
```

然后计算接收端噪声与信噪比：

```text
compute_noise_metrics()
```

输出包括：

| 字段 | 含义 |
|---|---|
| `power_observed_raw` | 观测回波功率 |
| `power_observed_noisy_raw` | 可选随机带噪功率 |
| `noise_std_power_W` | 等效功率噪声标准差 |
| `noise_floor_rms_W` | RMS 噪声底 |
| `snr_linear` | 线性信噪比 |
| `snr_db` | dB 信噪比 |

摘要函数：

| 函数 | 输出 |
|---|---|
| `raw_power_summary()` | 峰值功率、峰值距离、累计功率 |
| `snr_curve_summary()` | 峰值 SNR、指定距离 SNR、SNR 达标距离 |
| `depol_curve_summary()` | 退偏振曲线最小值、最大值等 |

## 10. 结果写入层

当前输出目录通常为：

```text
temp/lidar_1d/outputs_high_precision_latest/local/
```

主要输出文件：

| 文件/目录 | 内容 |
|---|---|
| `summary.json` | 全局参数、场景光学参数、SNR 摘要、退偏振摘要、缓存身份 |
| `params.json` | 本次有效输入参数快照 |
| `data/*.csv` | 每条曲线的距离、功率、噪声、SNR、归一化值 |
| `figures/*.png` | PNG 图像 |
| `figures/*.svg` | SVG 矢量图 |
| `optical_cache/*.json` | 光学计算缓存 |

成功后，前端调用：

```text
app/demo_ui.py::save_run_to_history()
```

底层调用：

```text
src/cache_runtime.py::archive_local_result()
```

将当前结果归档到：

```text
temp/lidar_1d/run_history/run_xxxxxxxx/
```

同时更新：

```text
temp/lidar_1d/run_history/manifest.json
temp/lidar_1d/runtime_state/active_view.json
```

## 11. 结果读取与展示层

UI 读取文件，而不是读取计算过程内存。

主要读取函数：

| 文件 | 函数 | 读取内容 |
|---|---|---|
| `app/demo_ui.py` | `load_summary()` | 当前活动结果的 `summary.json` |
| `app/demo_ui.py` | `load_csv()` | 当前活动结果的 `data/*.csv` |
| `src/cache_runtime.py` | `get_run_paths()` | 根据 active view 解析结果路径 |
| `src/cache_runtime.py` | `load_active_view()` | 读取当前活动结果 ID |

右侧图表由：

```text
_build_right_panel_with_refresh()
```

构建。

图表读取关系：

| 展示页 | 函数 | 读取文件 |
|---|---|---|
| 雾功率 | `fig_fog_power()` | `radiation_fog_power.csv`、`advection_fog_power.csv` |
| 霾功率 | `fig_haze_power()` | 四类霾 `*_power.csv` |
| 霾退偏振 | `fig_haze_depol()` | 四类霾 `*_depolarization.csv` |
| 雨功率 | `fig_rain_power()` | `rain_power.csv` |
| 全场景 SNR | `fig_all_snr()` | 各功率 CSV 中的 `snr_db` |
| 全场景对比 | `fig_all_power()` / `fig_all_depol()` | 各场景功率和退偏振 CSV |

数值摘要表由：

```text
render_summary_table()
```

读取 `summary.json` 中的：

```text
alpha_total
beta_total
depol_ratio
snr_summary
precision_warnings
```

## 12. 一句话总结

前端参数先被整理成 `param_overrides.json`；核心脚本读取它后生成实际参与计算的场景参数，并依次完成光学散射、雷达方程、噪声/SNR 和退偏振计算；结果统一落盘为 `summary.json + params.json + CSV + 图像`；前端再通过 `load_summary()` 和 `load_csv()` 从活动结果目录读取并展示。
